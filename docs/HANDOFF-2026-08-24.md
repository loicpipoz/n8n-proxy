# Reprise n8n-proxy Spiritviews

Etat confirme le 24 aout 2026. Cette note permet de reprendre l'exploitation
de l'ingress public n8n sans dependre de l'historique de conversation.

## Resume executif

Le chemin public est :

```text
Internet -> Nginx Proxy Manager -> Caddy n8n-proxy -> Tailscale -> n8n
```

Nginx Proxy Manager (NPM) termine TLS. Caddy applique l'allowlist de chemins et
de methodes, verifie l'adresse du pair NPM et un secret partage, puis rejoint
n8n par le tailnet. Les consoles d'administration SpiritSELF et SpiritBooking
ne sont pas exposees publiquement : elles restent accessibles par le tailnet,
puis protegees par la session admin et le controle CSRF de SpiritSELF.

L'ingress public SpiritBooking est operationnel. La derniere verification a
confirme que n8n recoit une IPv4 publique routable dans
`x-spirit-client-ip`, sans recevoir le secret NPM-Caddy.

## Configuration active

Variables importantes du `.env` non versionne :

```env
PUBLIC_DOMAIN=n8n-wh01.spiritviews.com
N8N_UPSTREAM_URL=https://100.110.202.6
N8N_UPSTREAM_HOST=n8n.monkey-eel.ts.net
N8N_UPSTREAM_TLS_SERVER_NAME=n8n.monkey-eel.ts.net
WEBHOOK_METHODS="GET POST OPTIONS"
WEBHOOK_PATHS="/webhook/0key/*"
ALLOWED_SOURCE_CIDRS="172.18.0.1/32"
NPM_EDGE_KEY=<secret hors Git>
```

`FORM_PATHS` inclut encore `/form-test/*`. Cette exposition est temporaire et
doit etre retiree apres inventaire des formulaires qui l'utilisent.

Dans la Custom Location `/` du Proxy Host NPM, les directives essentielles
sont :

```nginx
proxy_set_header X-Spirit-Edge-Key "<meme secret que NPM_EDGE_KEY>";
proxy_set_header X-Spirit-Client-IP $remote_addr;
```

Elles doivent etre placees dans le champ Advanced de la Custom Location `/`,
pas seulement dans l'onglet Advanced principal. NPM genere lui-meme un
`location /`, ce qui empeche sinon la transmission attendue.

L'onglet Advanced principal ne masque que les pannes de passerelle :

```nginx
proxy_intercept_errors on;
error_page 502 504 = @generic_gateway_error;

location @generic_gateway_error {
    default_type application/json;
    add_header Cache-Control "no-store" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Retry-After "30" always;
    return 503 '{"status":"service_unavailable"}';
}
```

Caddy exige simultanement : chemin autorise, methode autorisee, source
immediate NPM dans `ALLOWED_SOURCE_CIDRS` et valeur exacte de
`X-Spirit-Edge-Key`. Il supprime ensuite ce secret avant n8n. L'adresse cliente
est transmise dans `X-Spirit-Client-IP` pour l'audit uniquement. Elle ne doit
jamais servir seule a authentifier un utilisateur ou autoriser une mutation.

Dans n8n, la valeur est lisible avec :

```javascript
$json.headers['x-spirit-client-ip']
```

## Reseau Docker et Swarm

NPM transfere vers la passerelle hote `172.17.0.1:8080`. Caddy voit NPM par
`172.18.0.1`, d'ou l'allowlist `/32` actuelle. Le port Caddy `8080` ne doit pas
etre ouvert par le pare-feu public.

Les ports NPM `80` et `443` sont publies par Swarm en `mode: host`. Le service
est contraint au noeud unique :

```yaml
deploy:
  replicas: 1
  placement:
    constraints:
      - node.hostname == ov-bb434f.infomaniak.ch
  update_config:
    order: stop-first
    failure_action: rollback
  restart_policy:
    condition: any
```

Le passage en `mode: host` n'a pris effet qu'apres recreation forcee de la
tache NPM :

```bash
docker service update --force rustdesk_nginx-proxy-manager
```

Avant cette recreation, NPM voyait une adresse interne Swarm. Apres celle-ci,
`$remote_addr` correspond bien a l'adresse publique du client.

Le port d'administration NPM `8081` reste publie par Swarm, mais son acces
externe a expire lors du test, ce qui indique un blocage pare-feu. Ce blocage
doit rester explicite et surveille. A terme, il est preferable de rendre cette
administration accessible uniquement depuis le tailnet.

## Preuves de fonctionnement

Tests confirmes :

- `GET /webhook/0key/spiritbooking` public avec User-Agent navigateur : `200`.
- `/`, `/webhook/spiritself-admin` et les routes admin SpiritBooking publiques :
  `404`.
- `/webhook/spiritself-admin` par le tailnet : `200`.
- Routes admin reservations et facturation par le tailnet sans session : `401`.
- Le port Caddy `8080` n'a pas repondu depuis Internet.
- Le port NPM admin `8081` n'a pas repondu depuis Internet.

Une requete `curl` avec son User-Agent par defaut peut recevoir `403`, car le
Webhook n8n SpiritBooking active le filtre `ignoreBots`. Utiliser un User-Agent
de navigateur pour le test de disponibilite.

## Commandes d'exploitation

Mettre a jour et valider Caddy :

```bash
cd /chemin/vers/n8n-proxy
git pull --ff-only
docker compose config --quiet
docker exec n8n-proxy-caddy caddy validate --config /etc/caddy/Caddyfile
docker compose up -d --force-recreate caddy
```

Tester le webhook public :

```bash
curl -sS -o /dev/null -w '%{http_code}\n' \
  -A 'Mozilla/5.0 AppleWebKit/605.1.15 Safari/605.1.15' \
  https://n8n-wh01.spiritviews.com/webhook/0key/spiritbooking
```

Inspecter NPM dans Swarm :

```bash
docker service inspect rustdesk_nginx-proxy-manager \
  --format '{{json .Endpoint.Spec.Ports}}' | jq
docker service ps rustdesk_nginx-proxy-manager
```

Valider la configuration Nginx du conteneur NPM :

```bash
NPM_CONTAINER=$(docker ps --filter name=rustdesk_nginx-proxy-manager -q | head -1)
docker exec "$NPM_CONTAINER" nginx -t
docker exec "$NPM_CONTAINER" nginx -s reload
```

## Rollback

- Erreur NPM : retirer la directive fautive, valider avec `nginx -t`, puis
  recharger Nginx.
- Mauvaise mise a jour Swarm :
  `docker service rollback rustdesk_nginx-proxy-manager`.
- Mauvaise mise a jour Caddy versionnee : creer un `git revert`, pousser, puis
  recreer le service Caddy. Ne pas utiliser `git reset --hard`.

## Prochaine etape prioritaire

Ajouter un rate limiting par IP dans NPM, car cette couche voit maintenant la
vraie adresse publique. Definition proposee dans le fichier persistant du VPS
`/home/cloud-user/rustdesk-server-pro/npm/data/nginx/custom/http_top.conf` :

```nginx
limit_req_zone $binary_remote_addr zone=spiritbooking_public_per_ip:10m rate=10r/s;
```

Puis, dans l'Advanced de la Custom Location `/` :

```nginx
limit_req zone=spiritbooking_public_per_ip burst=30 nodelay;
limit_req_status 429;
```

Avant publication, verifier que la reponse `429` conserve le comportement CORS
attendu par SpiritBooking. Tester ensuite une reservation normale, une rafale
controlee qui doit produire `429`, puis le retour a `200` apres la fenetre.
